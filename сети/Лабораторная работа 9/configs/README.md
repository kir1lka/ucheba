## Этапы
1. Исходная сеть: Sw1 (2960), PC0–PC8, Server0. Адреса 10.10.4.101–110/24, шлюз и DNS пустые. Порты текущего файла laba99: PC0–PC5 на Fa0/1–6, PC8 на Fa0/7, PC7 на Fa0/8, PC6 на Fa0/9, сервер на Fa0/10. Проверить ping PC0 до сервера и PC3. В симуляции отправить широковещательный пакет 10.10.4.255, показать распространение на все порты. Сохранить LR_9-0-1_Blinov.pkt.
2. Применить 01_Sw1_VLAN.txt. Сначала сохранить одинаковую подсеть на хостах, проверить PC0–PC1 (должен проходить), PC0–PC3 (должен не проходить). В симуляции показать, что broadcast остаётся в VLAN. Затем сменить IP на отдельные подсети по строкам VLAN-separated в address-plan.csv, шлюз пустой. Сохранить LR_9-0-2_Blinov.pkt.
3. Расширенная сеть: переименовать PC0–2 в PC-Buh1–3; PC3–5 в PC-Sal1–3; PC6–8 в PC-Mark1–3. Добавить Sw2 (2960), шесть PC (по два на отдел), Sw-TR (3560). Исходный Server0 отключить от Sw1 Fa0/10 и перенести на Sw-TR Gig0/1 как DNSSrvr, добавить WebSrvr на Gig0/2. На серверах заменить сетевые модули на гигабитные при выключенном питании. Проверить фактическое имя серверного интерфейса.
4. Кабели EtherChannel: Sw1 Fa0/10–13 со Sw-TR Fa0/1–4; Sw2 Fa0/10–13 со Sw-TR Fa0/5–8. Все четыре кабеля каждой группы соединяют одну и ту же пару устройств. Создать каналы в shutdown, согласовать trunk и channel-group, затем поднять. Применить 02,03,04. На Sw-TR два Port-channel, на обоих периферийных коммутаторах допустим локальный Po1. Транки пропускают VLAN41–43; серверная VLAN45 нужна только локально на Sw-TR, поэтому передавать её на access-коммутаторы не требуется.
5. До ip routing проверить связь одинаковой VLAN между Sw1 и Sw2 и отсутствие связи между VLAN. Сохранить LR_9-1_Blinov.pkt. Затем применить 05_Sw_TR_Routing.txt, прописать шлюзы из routed-плана и адреса серверов. Сохранить LR_9-2_Blinov.pkt. Проверить ping между VLAN, с каждого отдела к обоим серверам, show vlan brief, show etherchannel summary, show interfaces trunk, show ip interface brief, show ip route. Реальные скриншоты с курсором вне окна.

## Исправления противоречий методички
- В примере адрес DNSSrvr .1 совпадает с SVI серверной VLAN .1. Сохраняем единообразный шлюз 10.45.4.1, серверам назначаем 10.45.4.10 и 10.45.4.20. Так исключён конфликт IP; маска /24.
- На 2960 не вводится switchport trunk encapsulation dot1q: он поддерживает только 802.1Q. Эта команда присутствует только на 3560.
- Методичка ошибочно предлагает show из глобального config без do. Файлы команд выходят в привилегированный режим перед show.
- ip routing на 3560 включает межсетевую маршрутизацию; для непосредственно подключённых SVI статические ip route не требуются. В show ip route ожидаются C, а не статические S.
- Надпись «Для Sw3» на странице17 относится к Sw_TR.
- Разрешённые VID для пользовательских VLAN 1–4094, номера 0 и 4095 зарезервированы; утверждение 1–4096 неточно.
- В расширенном этапе пример перенумеровывает хосты в пределах каждого отдела (101–105). Поэтому routed-план отличается от VLAN-separated для Sales и Market: это намеренная перенумерация по рисунку и таблице3.4.
